# План разработки «Деканат+»

Рабочий документ: цель, принятые решения, текущий статус и что осталось.

## 1. Цель и ограничения

Нужен сайт, который открывается по ссылке в браузере и работает с телефона.
Нативное приложение не подходит: жюри не сможет открыть APK по ссылке. Поэтому
сделан один адаптивный веб-клиент, собранный в PWA.

Ограничения конкурса, которые влияют на реализацию:

- приём работ — 8 ноября, итоги — 28 ноября;
- сайт должен открываться из РФ без VPN;
- нельзя использовать реальные данные и логотип вуза;
- прототип не должен подключаться к системам вуза.

## 2. Концепция

Кабинет строится вокруг вопроса «что у меня сейчас». Первый экран показывает
следующую пару, ближайший дедлайн, активные заявки. Остальные
разделы — в одно касание из нижнего меню. Дополнительно есть помощник, который
отвечает по данным кабинета и умеет открывать форму заявки.

Отдельный сценарий — кабинет сотрудника деканата: он видит заявки всех студентов и
меняет статусы. Это показывает, что статусы в студенческом кабинете живые.

Что сознательно не делали: стипендии, общежитие, портфолио. В прототипе важнее
связность основных сценариев, чем количество экранов.

Карта корпусов добавлена отдельным MVP: один корпус, четыре этажа, схематичные
планы в `src/assets/campus/`, хотспоты аудиторий в `src/data/campus.ts`. Схемы
легко заменить на сгенерированные картинки, координаты подгоняются в
`/campus?edit=1`.

## 3. Экраны

| Маршрут | Назначение |
|---|---|
| `/` | Лендинг: описание, дисклеймер, вход в демо |
| `/login` | Логин и пароль, быстрый вход в демо |
| `/demo` | Тестовые аккаунты, проверка изоляции данных |
| `/home` | Следующая пара, дедлайн, учёба, заявки |
| `/schedule` | День и неделя, замены и переносы |
| `/grades` | Оценки, зачёты, кредиты, долги, дедлайны |
| `/deadlines` | Отдельная страница дедлайнов: группы по срочности |
| `/campus` | Карта корпусов: этажи, поиск и подсветка аудитории |
| `/requests` | Список заявок, каталог типов |
| `/requests/new` | Форма заявки в три шага |
| `/requests/:id` | Статус, таймлайн, отмена |
| `/notifications` | Объявления, изменения, статусы, дедлайны |
| `/assistant` | Помощник на весь экран |
| `/profile` | Данные студента, тема, установка PWA |
| `/staff` | Кабинет сотрудника: заявки и статусы |
| `/403` | Отказ в доступе к чужой заявке |

## 4. Принятые решения

- **Стек:** Vite, React 19, TypeScript, Tailwind CSS 4, React Router.
  Даёт статическую сборку и простой деплой на любой хостинг.
- **Роутинг:** HashRouter — ссылка работает из подпапки GitHub Pages без настройки
  сервера.
- **Данные:** вымышленные данные в `src/data/seed.ts`, состояние в `localStorage`.
  Слой доступа вынесен в `src/lib/store.tsx`, чтобы позже заменить его на API.
- **Пароли:** в данных только SHA-256 хэши, сравнение через WebCrypto. Сессия
  хранится в браузере.
- **Изоляция данных:** заявка ищется по `id` из сессии, а не из URL. Чужая заявка
  даёт 403.
- **Помощник:** локальные правила в `src/lib/assistant.ts`, без внешних API и
  ключей. Ответы строятся по данным студента.
- **Демо-режим:** новая заявка автоматически проходит статусы за минуту, чтобы
  был виден процесс. Сбрасывается кнопкой «Сбросить демо».
- **PWA:** манифест и service worker с офлайн-заглушкой, установка на главный
  экран.
- **Доступность:** focus-visible, aria-атрибуты, `prefers-reduced-motion`,
  контрастные цвета, адаптив от 360 px.

## 5. Что осталось за рамками прототипа

- Настоящий backend: сессии на сервере, база данных, загрузка документов.
- Интеграция с расписанием и учётными системами вуза.
- Роли и права кроме студента и сотрудника деканата.
- Push-уведомления и почтовые уведомления.
- Электронная подпись и выдача документов.

## 6. Чек-лист перед сдачей

- [ ] Ссылка открывается из РФ без VPN, в том числе с телефона
- [ ] Видно, что это концепт, а не официальный сервис
- [ ] Логотип вуза не используется
- [ ] Вход работает: два студента и сотрудник, данные разные
- [ ] Студент не может открыть данные другого студента по прямой ссылке
- [ ] Пароли хранятся как хэши, ключей в коде и бандле нет
- [ ] Все данные вымышленные
- [ ] Расписание: день и неделя, аудитория, преподаватель, изменения
- [ ] Оценки, зачёты и долги понятны с одного экрана
- [ ] Заявка создаётся и меняет статус
- [ ] Уведомления работают
- [ ] Экран 360 px: нет горизонтального скролла
- [ ] Пустые состояния, загрузка и ошибки предусмотрены
- [ ] Репозиторий открыт для жюри
- [ ] PDF-описание и видео подготовлены
- [ ] Ссылки и тестовые аккаунты вставлены в комментарий к работе
