# Деканат+ — концепт цифрового деканата будущего

Рабочий прототип личного кабинета студента для конкурса «Цифровой деканат будущего».
Веб-приложение (адаптив от 360 px, устанавливается как PWA) с помощником, который
отвечает по данным кабинета.

> ⚠️ **Это концепт для конкурса, а не официальный сервис вуза.**
> Все ФИО, группы, оценки, преподаватели и документы вымышлены. Логотип вуза не
> используется. Демо не подключено к реальным системам.

---

## Быстрый старт (VS Code)

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`.

Сборка и локальный предпросмотр Production-версии:

```bash
npm run build
npm run preview
```

Требуется Node.js 20+.

## Демо-аккаунты

| Роль | Логин | Пароль | Что показывает |
|---|---|---|---|
| Студент | `anna` | `demo1234` | 3 курс, 2 активные заявки, без долгов |
| Студент | `mark` | `demo1234` | 2 курс, долг по дискретной математике |
| Сотрудник деканата | `dekanat` | `staff1234` | видит все заявки и меняет статусы |

Быстрый вход — на странице `#/demo` (кнопка «Войти как …»), пароль вводить не нужно.
Там же ссылка для проверки изоляции данных: заявка другого студента → экран 403.

## Что реализовано (обязательное ядро)

- **Вход и профиль** — логин/пароль, ФИО, институт, направление, курс, группа,
  зачётка, куратор, контакты.
- **Расписание** — сегодня / неделя, аудитория, преподаватель, бейджи переноса,
  замены и отмены, обратный отсчёт до следующей пары.
- **Успеваемость** — оценки, зачёты, средний балл, зачётные единицы, «здоровье
  сессии», долги, дедлайны.
- **Заявки и справки** — 6 типов заявок, форма в 3 шага, список, таймлайн статусов,
  ETA, отмена, номер для обращения.
- **Уведомления** — объявления деканата, изменения расписания, статусы заявок,
  дедлайны, непрочитанные.

## Дополнительно

- **Помощник деканата** — чат на локальных правилах (без внешних API и ключей):
  расписание, окна, оценки, долги, дедлайны, создание заявок.
- **Демо-режим заявок** — новая заявка проходит статусы за минуту с уведомлениями.
- **Кабинет сотрудника** — фильтры, поиск, смена статусов, публикация решения.
- **PWA** — установка на главный экран, офлайн-оболочка.
- Тёмная тема, пустые состояния, скелетоны, доступность (focus-visible,
  aria-атрибуты, `prefers-reduced-motion`).

## Безопасность (что и как проверять)

1. **Чужие данные недоступны.** Заявка ищется по `id` из сессии: войдите как Анна и
   откройте `#/requests/req_2001` — будет 403.
2. **Пароли не хранятся в открытом виде.** В данных только SHA-256 хэши
   (`src/data/seed.ts`), сравнение — через WebCrypto.
3. **Нет ключей и внешних API.** Помощник работает на правилах, ключей в бандле нет.
4. **Только вымышленные данные.** Никаких реальных ФИО и подключений к системам вуза.

Ограничение прототипа: данные лежат в браузере (`localStorage`), сервера нет. Для
конкурса этого достаточно; для продакшена нужен backend с сессиями и БД — архитектура
вынесена в `src/lib/store.tsx`, её можно заменить на API без переписывания экранов.

## Структура проекта

```
src/
├── data/seed.ts          # все вымышленные данные: студенты, расписание, заявки
├── lib/
│   ├── types.ts          # модели данных
│   ├── auth.tsx          # вход, хэширование пароля, сессия, тема
│   ├── store.tsx         # заявки, уведомления, демо-статусы
│   ├── assistant.ts      # правила помощника
│   └── utils.ts          # даты, склонения, форматирование
├── components/           # оболочка, UI-кит, помощник, таймлайн заявок
└── pages/                # экраны
docs/
├── PLAN.md               # план работы и идеи
├── ОПИСАНИЕ-ПРОЦЕССА.md  # заготовка описания для сдачи
└── СЦЕНАРИЙ-ДЕМО.md      # сценарий видео и прогулка для жюри
```

**Где менять данные:** `src/data/seed.ts` (студенты, пары, оценки, заявки).
**Где менять тексты помощника:** `src/lib/assistant.ts`.

## Деплой

### GitHub Pages (бесплатно, доступно из РФ)

1. Запушьте репозиторий в GitHub (ветка `main`).
2. Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` соберёт и опубликует сайт.
4. Ссылка: `https://<username>.github.io/<repo>/`.

Сборка использует `base: './'` и HashRouter, поэтому работает из подпапки.

### Альтернативы

- **Cloudflare Pages**: build command `npm run build`, output `dist`.
- **Timeweb Cloud / Beget / VK Cloud** — любой статический хостинг, папка `dist`.
- **Vercel/Netlify** — тоже подойдут, но проверьте доступность из РФ без VPN.

После деплоя обязательно проверьте: вход, все разделы, 360 px, чужую заявку → 403.
