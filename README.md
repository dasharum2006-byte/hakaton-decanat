# Деканат+ — цифровой деканат будущего

Рабочий прототип личного кабинета студента, в котором учёба, документы и связь с
деканатом собраны в одном месте. Сделан для хакатона Цифровой деканат будущего - версия сайта и мобильная версия
**Демо-режим:** вход в один клик за студента, сотрудника деканата или преподавателя,
все сценарии проходятся без регистрации и внешних сервисов.

---

## Проблема и решение

| Как сейчас | Как в «Деканат+» |
|---|---|
| Расписание на одном сайте, оценки — в другой системе, также из за разрозненной системы можно пропустить дедлайны, с преподавателями можно переписываться только по вузовской почте, а они могут долго туда не заходить | Единый кабинет: расписание, оценки, дедлайны,заявки,чаты |
| Справка — через очередь в деканате | Заявка онлайн за три шага, со статусом и сроком |
| Объявления — в чатах и на почте | Уведомления с типами: объявления, переносы, отмены, дедлайны |
| Непонятно как у меня дела | Экран «Учёба»: средний балл, зачёты, долги, работы и баллы |
| С телефона неудобно | Интерфейс с 360 px, нижняя навигация, PWA-установка |

| Требование | Что реализовано |

| **Расписание** | День / неделя / месяц, листание периодов, аудитория и преподаватель, переносы, замены и отмены, дедлайны на своём дне, прогресс текущей пары |
| **Успеваемость** | Оценки и зачёты, средний балл, зачётные единицы, долги, работы с баллами, «Как у меня дела» и прогресс по дисциплинам |
| **Заявки и справки** | 6 типов заявок, форма в три шага, список, таймлайн статусов, срок готовности, отмена, номер обращения |
| **Уведомления** | Новости деканата, изменения расписания, статусы заявок, напоминания о дедлайнах, непрочитанные, цветовая маркировка типов |

## Что добавили сверх обязательного

- **Карта корпусов**: схемы этажей, поиск аудитории, подсветка пар на сегодня,
  масштабирование.
- **Помощник «Декот»**: чат-ассистент в виде кота может подсказать расписание, окна,
  оценки, долги, дедлайны и оформление заявок без внешних API.
- **Переписка с преподавателем**: студент пишет со страницы дисциплины, преподаватель
  отвечает в разделе «Сообщения»; у студента также есть  вкладка «Чаты».
- **Кабинет преподавателя**: приветствие по времени суток, пары на сегодня,
  расписание на день/неделю/месяц, сообщения студентов.
- **Кабинет сотрудника деканата**: все заявки, фильтры, поиск, смена статусов.
- **Прикрепление выполненных работ** к позициям «Работы и баллы».
- **Своя иконка профиля** с проверкой формата и безопасной обработкой картинки.
- **Тёмная тема, PWA-установка, анимации** есть спящий кот,когда нет пар, во кладке столовая - он кушает,если студент получил зачет или сдал экзамен, то он хвалит его


Прототип показывает не только студента, но и вторую сторону процесса:

1. **Студент** — учится, смотрит долги, подаёт заявки, пишет преподавателю.
2. **Сотрудник деканата** — обрабатывает заявки: берёт в работу, подписывает, выдаёт.
3. **Преподаватель** — видит свои пары, студентов и сообщения.

## Безопасность и приватность

- у каждого студента видны только собственные данные: заявка ищется по сессии,
  чужая ссылка даёт отказ;
- пароли хранятся как SHA-256-хэши, в открытом виде их нет;
- загружаемая иконка профиля проверяется и пользователь может загрузить только PNG/JPEG,
  ограничена по размеру и **перекодируется через canvas** — метаданные и посторонние
  данные не попадают в приложение;
- прикрепляемые файлы проверяются по расширению и размеру, содержимое никуда не
  отправляется;
- всё работает в браузере.

## Мобильность и доступность
- вёрстка от 360 px, нижняя навигация, крупные тапы;
- PWA: установка на главный экран, офлайн-оболочка;
- тёмная и светлая темы, `prefers-reduced-motion`, `focus-visible`, aria-атрибуты.

## Своя иконка профиля
В профиле можно нажать на аватар и загрузить свою картинку (модалка «Иконка профиля»).
Ограничения и защита:
- принимаются только **PNG и JPEG** — проверяется и MIME-тип, и сигнатура файла
  (переименованный SVG/GIF не пройдёт);
- лимит 2 МБ, стороны исходника до 4096 px;
- картинка декодируется браузером, обрезается в квадрат 256×256 и **заново
  кодируется в PNG через canvas** — метаданные и посторонние вложенные данные
  отбрасываются, SVG/HTML/JS внутрь не попадут;
- в `localStorage` хранится только data-URL PNG фиксированной длины, префикс
  проверяется при чтении (подмена на `javascript:` удаляется);
- ничего не отправляется на сервер: иконка живёт в браузере, кнопка «Вернуть
  букву» сбрасывает её к инициалам.

## Разделы

- **Вход и профиль** — логин и пароль, ФИО, институт, направление, курс, группа,
  зачётная книжка, куратор, контакты.
- **Расписание** — день, неделя и месяц, листание недель и месяцев вперёд и
  назад, аудитория, преподаватель, отметки о переносе, замене и отмене. В полосе
  дней и в календаре месяца — точки по числу пар с цветом по типу занятия
  (лекция, практика, лабораторная), выходные подписаны красным. У пары, которая
  идёт сейчас, показывается прошедшее время и полоса прогресса. Дедлайны из
  «Учёбы» попадают в расписание на свой день, в календаре месяца отмечены красной
  чертой.
- **Успеваемость** — оценки и зачёты, средний балл, зачётные единицы, долги.
  Практические работы по дисциплинам в процессе создаются автоматически.
- **Дедлайны** (`/deadlines`) — отдельная страница: ближайший дедлайн, группы
  «Просрочено / Сегодня / Завтра / На этой неделе / Позже», переход в неё — из
  карточки «Дедлайны» на странице «Учёба» и из блока «Ближайший дедлайн» на
  главной. Дедлайн на завтра помечается красным, на 2–3 дня — жёлтым.
- **Заявки и справки** — шесть типов заявок, форма в три шага, список, таймлайн
  статусов, срок готовности, отмена, номер для обращения.
- **Уведомления** — объявления деканата, изменения расписания, статусы заявок,
  напоминания о дедлайнах («сегодня» / «завтра» / «через 2–3 дня»), непрочитанные.
  При входе напоминание на сегодня и завтра показывается всплывающим сообщением.
- **Карта корпусов** — схема этажей одного корпуса. Как пользоваться: нажми на
  помещение на схеме или введи номер аудитории в поиске сверху; этажи
  переключаются кнопками; у аудиторий, где сегодня есть пары, стоит точка, а в
  карточке аудитории видно расписание на сегодня. Открывается из расписания и с
  главной: тап по «ауд. 401» ведёт сразу на нужный этаж
  (`/#/campus?room=401`). Картинки этажей — `src/assets/campus/floor-*.svg`
  (заменяются на любые сгенерированные схемы), координаты аудиторий —
  `src/data/campus.ts`. Подгонять координаты удобно в режиме
  `/#/campus?edit=1`: клик по карте печатает `x, y` в процентах.
- **Помощник деканата** — чат на локальных правилах: расписание, окна, оценки,
  долги, дедлайны, создание заявок.
- **Кабинет сотрудника** — фильтры, поиск, смена статусов, публикация решения.
- **Демо-режим заявок** — новая заявка проходит статусы за минуту.
- **PWA и темы** — установка на главный экран, офлайн-оболочка, светлая и тёмная
  темы, `prefers-reduced-motion`, focus-visible, aria-атрибуты.


## Обозначения в расписании

**Цветные точки** в полосе дней и в календаре месяца показывают типы занятий:

| Цвет | Тип занятия |
|---|---|
| Насыщенный синий | Лекция |
| Тёплый оранжевый | Практика |
| Мягкий фиолетовый | Лабораторная |
| Серый | Семинар |
| Зелёный | Консультация |
| Красный | Зачёт или экзамен |

**Чередование недель.** Часть пар идёт только по чётным или только по нечётным
неделям. Номер недели считается от 1 сентября: неделя, в которую попадает
1 сентября, — первая. В шапке расписания показывается номер недели, например
«10 неделя».

**Дедлайны.** Дедлайны из «Учёбы» появляются в расписании на свой день отдельной
карточкой с красной полосой. Например, если практическая по истории сдаётся
завтра, в расписании на завтра будет карточка «Практическая 3 · История России ·
до 18:00».

**Работы из основной системы.** Контрольные, тестирования и коллоквиумы
привязываются к паре по предмету и показываются  справа:

- контрольная работа и тестирование — к паре типа «Практика»;
- коллоквиум — к «Лекции».

Пример: «Контрольная работа 1» по математическому анализу с диапазоном
10–18 ноября встанет на ближайшую практику по матанализу в этих числах, а не на
произвольный день. Если подходящей пары в диапазоне нет, бейдж не появится.

## Ограничения и безопасность

1. Чужие данные недоступны: заявка ищется по `id` из сессии. Войдите как Анна и
   откройте `#/requests/req_2001` — будет 403.
2. Пароли не хранятся в открытом виде: в данных только SHA-256 хэши
   (`src/data/seed.ts`), сравнение через WebCrypto.
3. Внешних API и ключей нет, помощник работает на правилах.
4. Данные лежат в `localStorage`, сервера нет. Для продакшена нужен backend с
   сессиями и базой; слой данных вынесен в `src/lib/store.tsx`, поэтому экраны
   можно перевести на API без переписывания.

## Структура

```
src/
├── data/seed.ts          # вымышленные данные: студенты, расписание, заявки
├── lib/
│   ├── types.ts          # модели данных
│   ├── auth.tsx          # вход, хэширование пароля, сессия, тема
│   ├── store.tsx         # заявки, уведомления, демо-статусы
│   ├── assistant.ts      # правила помощника
│   ├── messages.ts       # переписка студент ↔ преподаватель
│   ├── attachments.ts    # файлы, прикреплённые к работам
│   ├── avatar.ts         # безопасная загрузка иконки профиля
│   └── utils.ts          # даты, склонения, форматирование
├── components/           # оболочка, UI-кит, помощник, таймлайн заявок
└── pages/                # экраны
docs/
├── PLAN.md               # план работ и принятые решения
├── ОПИСАНИЕ-ПРОЦЕССА.md  # описание процесса для сдачи
└── СЦЕНАРИЙ-ДЕМО.md      # сценарий видео и демонстрации
```
Данные меняются в `src/data/seed.ts`, тексты помощника — в `src/lib/assistant.ts`.

## Деплой

### GitHub Pages

1. Запушьте репозиторий в GitHub (ветка `main`).
2. Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` соберёт и опубликует сайт.
4. Ссылка: `https://<username>.github.io/<repo>/`.

Сборка использует `base: './'` и HashRouter, поэтому работает из подпапки.

`localStorage`, бэкенда и внешних API нет.
